## Назначение

LectureFlow — **конструктор текстовых промптов** для дальнейшей работы с учебными материалами в выбранной пользователем внешней нейросети. Он **не анализирует и не загружает файл в нейросеть автоматически**, не формирует готовый конспект. Выбранный локальный файл не отправляется на сервер, его необходимо отдельно приложить к скопированному промпту во внешнем сервисе.

Работа №4 продолжает HTML-каркас работы №3. Реализован **статичный адаптивный интерфейс** по согласованным экранам Figma (`03_FINAL`: Desktop Final 1440 и Mobile Final 375); уже существующее небольшое поведение на JavaScript сохранено.

## Что изменено для ДЗ №4

- Отдельная таблица стилей `css/style.css`, корректно подключенная из `index.html`.
- Переменные `:root` для основных цветов, размеров, отступов, шрифтов и скруглений; общая блочная модель `border-box`.
- Единая визуальная система для шапки, главного экрана, формы, семи карточек, результата, памятки и подвала.
- **Flexbox:** шапка, карточки, кнопки/чипы, строка действий. **Grid:** форма, каталог карточек, композиция главного экрана и результата.
- Несколько медиазапросов: desktop и промежуточная ширина, планшет, mobile 375–390 px; на телефоне карточки перестраиваются в одну колонку и появляется адаптивное меню.
- Состояния элементов `:hover`, `:active`, `:focus-visible`, `:disabled`, состояние невалидных полей `:user-invalid` (там, где поддерживается браузером); выделение выбранной карточки через `.selected`.
- У блока результата и чек-листа **одинаковый радиус**: `24px` на большом экране и `18px` на мобильном — исправление замечания преподавателя.
- Сохранены выбор всех 7 пресетов, изменение параметров, создание текстового промпта, очистка устаревшего результата и возможность копирования.

## ДЗ № 5 — JavaScript, DOM и интерактивность (09.11.2026)

**Задача:** добавить не менее трёх работающих интерактивных сценариев в существующий проект. Реализованы и проверялись:

1. **Живой поиск** по заголовкам семи карточек в `#template-search`; нормализация регистра, краевых и повторных внутренних пробелов, включая проверку специальных символов.
2. **Фильтрация категорий** через `#template-category`. Одна функция `applyFilters()` учитывает и поисковый запрос, и категорию; меняет свойство `hidden`, счётчик `#template-count`, пустое состояние `#template-empty`. Кнопка «Сбросить» восстанавливает весь список.
3. **Подробная карточка**: кнопка «Подробнее» открывает общее нативное окно `#template-dialog` с данными выбранного шаблона; закрытие кнопкой, Escape; навигация Tab/Shift+Tab удерживается в диалоге.

Не изменены логика выбора семи пресетов, построение/очистка текста промпта, копирование и локальное отображение имени выбранного файла. Исходный учебный материал не загружается на сервер. Используются чистые HTML/CSS/JavaScript, без API, `fetch()` и сборки npm. Функции в `js/script.js`; подключение — через `defer`. Дополнительно создан `assets/favicon.svg` и подключён в `index.html`.

## ДЗ № 6 — JSON, Fetch API и динамическая отрисовка (26.11.2026)

Письменное задание `TASK 6.pdf` требует вывести карточки из `data/data.json` через `fetch()`, создавать элементы с JavaScript, показать сообщение при ошибке загрузки и сохранить интерактивность из ДЗ № 5. **В ветке ДЗ № 6 это реализовано:**

- Все **7** карточек, их категории (`notes`, `study`, `practice`), заголовки, описания, теги, иконки и параметры пресетов перенесены из `index.html` в **массив `data/data.json`** с одинаковым составом полей.
- Поля JSON: `id`, `title`, `category`, `description`, `tags`, `image`, `link`, `icon`, `preset`. Для `image` и `link` сейчас используется `null`: изображения и внешние ссылки в исходном проекте не были предусмотрены, поэтому никаких несуществующих ресурсов не добавлено.
- `loadTemplates()` делает `fetch("data/data.json")`, проверяет HTTP-ответ и структуру массива, а `createTemplateCard()` создаёт элементы безопасно через DOM API/`textContent`. В HTML больше нет вручную размеченных карточек; начальное состояние «Загрузка…», после ответа — семь карточек.
- Поиск, категории, сброс и модальное окно продолжают работать **после** загрузки. Для кликов по динамическим карточкам используется **делегирование событий** на контейнере, без повторного назначения обработчиков.
- При HTTP-ошибке, некорректном JSON и нарушении структуры показывается сообщение об ошибке и рабочая кнопка «Повторить загрузку».
- Сохранены ранее разработанные выбор пресета, заполнение формы, генерация и копирование промпта, адаптивная сетка и клавиатурное управление модальным окном.

**Ветки:** ДЗ № 6 находится в `hw6/json-fetch-render-20261126`, основана на уже проверенной `hw5/javascript-interactivity-20261109`. PR № 5 — отдельная проверка ДЗ № 6 поверх PR № 4. **`main` не изменяется**; ДЗ № 6 не опубликовано.

### Запуск и проверка ДЗ № 6

1. Загрузить ветку `hw6/json-fetch-render-20261126`.
2. Открыть папку в VS Code и запустить `index.html` через **Live Server**. Либо из папки проекта выполнить `python -m http.server 8000` и открыть `http://localhost:8000/`.
3. **Не открывать `index.html` через `file://`** — `fetch()` может быть заблокирован браузером. При такой ситуации интерфейс покажет подсказку.
4. Проверить DevTools → Network → `data/data.json` (успешный запрос), Console без ошибок, наличие семи карточек, живой поиск и фильтр, модалку, пресеты и генерацию текста.
5. Проверить сбой загрузки через DevTools → Network → Offline (перезагрузить страницу), затем Online и «Повторить загрузку»; сохранить скриншот Console для сдачи.
6. Для письменной сдачи: GitHub + временно опубликованный сайт **или** видео до двух минут, скриншот Console и `ai-log.md`.

### QA ДЗ № 6

Локальный набор Playwright/Chromium прошёл **384 PASS / 0 FAIL** на 375, 390, 768, 1024 и 1440 px. Он покрывает вывод семи карточек, категории, поиск с пробелами и регистром, совместные фильтры, модальное окно и клавиатуру, семь пресетов, формирование/копирование, отсутствие горизонтального переполнения, ошибки 404/неправильного JSON/схемы, повторную загрузку, инъекцию в `title` и Console в успешном сценарии. Локальный HTTP-сервер отдельно отдал `/index.html`, CSS, JS, JSON и favicon с кодом 200.

**Ограничение проверок:** среда блокировала навигацию Chromium на `localhost` (`ERR_BLOCKED_BY_ADMINISTRATOR`). Поэтому интерфейс тестировался через `set_content` с перехваченным ответом `fetch()` через Playwright Route; это **не** полноценный браузерный прогон через локальный сервер. Физический телефон для ДЗ № 6 и опубликованный сайт ещё не проверены. Полный протокол — `HW6_TEST_PLAN.md`, краткий машинный итог — `evidence/hw6_qa_summary.json`.

## Проверка ДЗ № 4 и ограничения

В отдельном браузерном QA-прогоне **выполнены** проверки рендера для ширин `1440, 1100, 850, 768, 600, 390, 375, 360, 320px`: нет горизонтального переполнения и обнаруженного обрезания текста; совпадают радиусы результата и чек-листа; все семь шаблонов выбираются; генерация/очистка промпта работают, мобильное меню открывается.

**Ограничение среды проверки:** браузерный контейнер блокирует прямые навигации `file://` и `http://localhost`. Поэтому для QA использован Chromium с загрузкой тех же локальных `index.html`, CSS и JS как отдельных текстовых ресурсов (`set_content`, затем `add_style_tag` / `add_script_tag`). Это подтверждает поведение и отображение **самого кода**, но не заменяет проверку на ПК через Live Server и на настоящем телефоне. Буфер обмена в реальном браузере зависит от разрешений контекста; предусмотрен запасной вариант выделения текста + Ctrl+C.

**Что не делалось:** публикация production-сайта, серверная обработка файла, добавление нового ИИ API, сборка полноценного backend. Созданный учебный проект не связан с `2md13.ru`.
